# SXUWhatEat 网站功能优化设计

## 目标

根据《网站功能测试与优化建议》完成当前版本主要可用性问题：恢复每日抽签核心能力，明确强制登录边界，修复筛选和表单校验，完善评论点赞表达、权限提示、操作反馈，并降低管理工作台的信息密度。

## 产品边界

- 首页、食堂窗口、个性筛选、每日抽签和管理端仍然必须登录后访问。
- 评论、点赞、回复和抽签继续由后端鉴权。
- 本轮不开放游客接口，不新增推荐算法。
- 本轮不新增管理员操作日志数据库；高风险用户停用使用二次确认。
- 示例菜品仅用于恢复开发与验收能力，后续可由管理员或 Excel 导入替换、补齐。

## 示例数据与后台概览

开发种子服务改为幂等合并，不再因已有任意地点而整体跳过。按稳定业务键补齐：

- 校内餐厅、小吃街、自定义方位三类地点。
- 至少 5 个店铺/窗口和 12 道示例菜品。
- 米、面、包子、粥等基础标签及辣、鲜、清淡、甜等味道标签。

`start.sh` 在 Alembic 迁移后执行开发种子。重复启动不会重复创建数据，也不会覆盖管理员已经修改的已有记录。

管理端概览从已加载的地点树派生：

- 可用地点数。
- 可用店铺数。
- 可抽签菜品数。
- 缺少菜品的店铺数。
- 缺少图片的店铺数。
- 缺少价格的菜品数。

可抽签菜品为 0 时显示发布阻断告警。

## 强制登录与导航

Next.js 中间件继续拦截所有业务页面，仅登录、注册和静态资源公开。首页入口补充“登录后使用”标记。

顶部导航根据当前 pathname 高亮栏目，并为当前链接设置 `aria-current="page"`。移动端允许横向滚动，避免导航按钮挤压。

普通用户访问 `/admin` 时显示“当前账号没有管理权限”，提供“返回首页”和“退出并切换管理员账号”，不再提示已登录用户再次直接登录。

## 个性筛选

采用严格筛选模式：

- 关键词必须命中地点、店铺或菜品字段，未命中则不展示店铺。
- 标签和价格条件必须由该店铺至少一道菜满足。
- 结果只展示满足菜品条件的菜品。
- 高赞和实景图条件继续作为严格布尔过滤。

价格输入只接受最多两位小数的非负数字。最低价高于最高价时显示字段错误并停止结果计算。筛选面板提供“清空全部条件”。

结果卡展示匹配依据，包括命中关键词、命中标签、价格符合、高赞和有实景图。

## 评论与点赞

- 评论和回复空白时禁用提交。
- 评论上限 1000 字，回复上限 500 字，显示实时字数。
- 图片提示明确仅支持 JPEG、PNG、WebP，压缩后不超过 1MB，每条评论 1 张。
- 评论成功后显示反馈，并滚动定位到新评论。
- 回复成功后显示反馈并展开回复列表。
- 店铺和评论点赞按钮显示“点赞”或“已点赞”及数量，请求期间禁用。
- 评论区标题分别显示主评论数量和回复数量。
- 回复默认折叠，提供展开和收起操作。

后端继续维护 `vendor.comment_count` 为主评论与回复总数；前端依据评论树分别展示两个数量。

## 管理工作台

管理端改为侧边导航和内容页签：

- 数据概览。
- 地点与楼层。
- 店铺与窗口。
- 菜品管理。
- 标签管理。
- 用户与管理员。
- 数据导入。

不拆新的 URL，保留 `/admin`，以本地页签降低风险并保持已有 API 合约。

新增表单统一行为：

- 必填字段显示星号。
- 必填或依赖项未完成时禁用提交。
- 依赖资源未选择时禁用后续字段。
- 提交期间禁用并显示处理中。
- API 错误显示在所属表单内。
- 成功后显示具体结果并刷新列表。

刷新按钮显示加载状态、成功或失败反馈和最后更新时间。用户停用或启用前显示确认。

既有地点、店铺、菜品和标签列表提供状态展示和启用/停用入口，复用现有 PATCH API；本轮不实现批量删除。

## 测试

- 后端：种子可补齐部分已有数据，重复执行不重复；三类地点和示例菜品可浏览；抽签有候选菜品。
- 前端规则测试：关键词严格过滤、标签/价格组合、非法价格区间、匹配依据、后台指标。
- 前端构建：`npm run typecheck` 和 `npm run build`。
- 浏览器：强制登录、首页登录标记、导航当前态、筛选校验、评论按钮状态、普通用户后台提示、管理页签和指标。
- 移动端：导航、筛选、评论和管理侧边页签无溢出或重叠。
